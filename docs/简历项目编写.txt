项目名称：智析 RAG（ZuoAI-Agent）

  ① 多通道并行检索
  为解决单一向量检索召回率不足的问题，自主设计双通道并行检索机制，基于
  CompletableFuture 同时发起全局向量检索与意图定向检索两条通路，结果按意图定向优
  先、全局补充的策略合并去重，显著提升答案召回率与准确率。

  ② Chat/Embedding 双维熔断路由
  为解决单一 AI 模型故障导致服务不可用的问题，自主设计多模型候选熔断路由机制，每
  个候选模型独立维护三态熔断器（CLOSED → OPEN →
  HALF_OPEN），达到失败阈值自动熔断、超时后自动探测恢复，实现 AI
  服务零感知故障转移。

  ③ 全链路流水线追踪
  基于 PostgreSQL 实现 RAG
  流水线全链路追踪，对查询改写、意图分类、多通道检索、重排序、Prompt 组装 5
  个阶段分别异步记录耗时与输入输出数据，支持每次对话的完整执行轨迹回溯，便于问题
  定位与效果分析。

  ④ 意图树三级分类动态缩小检索空间
  基于领域→类目→话题三级意图树结构，利用 LLM
  对用户查询进行意图分类，置信度高于阈值时将检索范围收敛至对应知识库，同时对系统/
  闲聊意图进行短路处理直接回复，减少不必要的向量检索开销。

  ⑤ 结构感知 Markdown 文档分块
  自主实现结构感知分块器，对 Markdown
  文档识别标题、代码围栏、原子行、段落四类结构块，仅在块边界切分，按
  min/target/max 三参数预算动态打包，避免语义割裂，提升 RAG
  检索时文档片段的语义完整性。

  ⑥ 基于 PostgreSQL 的持久化对话记忆与摘要压缩
  基于 PostgreSQL 实现跨会话对话记忆持久化，当会话消息数超过阈值时自动触发 LLM
  摘要压缩，将最旧的一半消息压缩为单条摘要 SystemMessage
  后写回数据库，在保留长期上下文语义的同时控制 Token 消耗。

  ⑦ SSE 流式回复全链路推送
  基于 Spring MVC SseEmitter 实现 RAG 流水线端到端流式回复，模型输出 Token
  实时推送至前端，结合路由 Chat
  服务的熔断重试机制，保障高延迟场景下用户仍能看到流式逐字输出，提升交互体验。

  ⑧ 查询改写降级容错
  对用户原始查询进行 LLM
  改写以补全语义缺失，改写阶段采用降级设计——改写失败时自动回退原始 Prompt
  继续执行，保证任意单点故障不阻断整条流水线，提升系统整体鲁棒性。

  ⑨ 多文档格式解析与向量入库
  基于 Spring AI 集成 PDF、Markdown、JSON 多格式文档解析，解析后经分块、Embedding
   向量化写入 PgVector
  向量数据库，支持知识库独立命名空间隔离，实现企业级知识库按库检索与统一管理。
