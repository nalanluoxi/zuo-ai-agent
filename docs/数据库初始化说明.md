# 数据库初始化说明

本文档说明如何在 Supabase 上完成项目数据库的初始化，包括开启扩展插件和创建所有业务表。

---

## 一、前置条件

- 已在 [Supabase](https://supabase.com) 创建项目
- 能进入项目控制台的 **SQL Editor**

---

## 二、初始化步骤

### 第一步：开启 pgvector 扩展

进入 Supabase 控制台 → **SQL Editor**，执行：

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

> pgvector 是 PostgreSQL 向量检索扩展，Spring AI 的向量存储功能依赖此插件。

---

### 第二步：执行建表脚本

将以下 SQL 完整粘贴到 SQL Editor 中执行（脚本来源：`src/main/resources/sql/knowledge.sql`）：

```sql
-- 知识库表
CREATE TABLE IF NOT EXISTS t_knowledge_base
(
    id          BIGINT PRIMARY KEY,
    name        VARCHAR(128) NOT NULL,
    description VARCHAR(512),
    created_by  VARCHAR(64),
    updated_by  VARCHAR(64),
    create_time TIMESTAMP    NOT NULL DEFAULT NOW(),
    update_time TIMESTAMP    NOT NULL DEFAULT NOW(),
    deleted     SMALLINT     NOT NULL DEFAULT 0
);

CREATE UNIQUE INDEX IF NOT EXISTS uk_knowledge_base_name ON t_knowledge_base (name) WHERE deleted = 0;

-- 知识库文档表
CREATE TABLE IF NOT EXISTS t_knowledge_document
(
    id          BIGINT PRIMARY KEY,
    kb_id       BIGINT       NOT NULL,
    doc_name    VARCHAR(256) NOT NULL,
    file_url    VARCHAR(1024),
    file_type   VARCHAR(64),
    file_size   BIGINT,
    source_type VARCHAR(32)  NOT NULL DEFAULT 'file',
    status      VARCHAR(32)  NOT NULL DEFAULT 'pending',
    enabled     SMALLINT     NOT NULL DEFAULT 1,
    created_by  VARCHAR(64),
    updated_by  VARCHAR(64),
    create_time TIMESTAMP    NOT NULL DEFAULT NOW(),
    update_time TIMESTAMP    NOT NULL DEFAULT NOW(),
    deleted     SMALLINT     NOT NULL DEFAULT 0
);

CREATE INDEX IF NOT EXISTS idx_knowledge_document_kb_id ON t_knowledge_document (kb_id);

-- 文件内容存储表（替代 MinIO，用 Supabase PostgreSQL 的 bytea 存储原始文件）
CREATE TABLE IF NOT EXISTS t_knowledge_document_file
(
    id           BIGSERIAL PRIMARY KEY,
    storage_key  VARCHAR(512) NOT NULL UNIQUE,
    content      BYTEA        NOT NULL,
    content_type VARCHAR(128),
    create_time  TIMESTAMP    NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_doc_file_storage_key ON t_knowledge_document_file (storage_key);
```

---

## 三、表结构说明

### t_knowledge_base（知识库）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键，雪花 ID（由 Java 生成） |
| name | VARCHAR(128) | 知识库名称，同名不可重复 |
| description | VARCHAR(512) | 描述 |
| created_by | VARCHAR(64) | 创建人 |
| updated_by | VARCHAR(64) | 修改人 |
| create_time | TIMESTAMP | 创建时间 |
| update_time | TIMESTAMP | 修改时间 |
| deleted | SMALLINT | 逻辑删除：0-正常，1-已删除 |

### t_knowledge_document（知识库文档）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键，雪花 ID |
| kb_id | BIGINT | 所属知识库 ID |
| doc_name | VARCHAR(256) | 文档原始文件名 |
| file_url | VARCHAR(1024) | 文件存储 key（对应 t_knowledge_document_file.storage_key） |
| file_type | VARCHAR(64) | 文件类型：pdf / md / docx 等 |
| file_size | BIGINT | 文件大小（字节） |
| source_type | VARCHAR(32) | 来源类型，默认 `file` |
| status | VARCHAR(32) | 处理状态：pending / success / failed |
| enabled | SMALLINT | 是否启用：1-启用，0-禁用 |
| deleted | SMALLINT | 逻辑删除：0-正常，1-已删除 |

### t_knowledge_document_file（文件内容）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGSERIAL | 自增主键 |
| storage_key | VARCHAR(512) | 唯一存储键（UUID + 文件名） |
| content | BYTEA | 文件二进制内容 |
| content_type | VARCHAR(128) | MIME 类型，如 `application/pdf` |
| create_time | TIMESTAMP | 上传时间 |

> **说明**：本项目使用 PostgreSQL 的 `bytea` 字段直接存储文件内容，替代 MinIO 对象存储。适合文件体积不超过 50MB 的场景。如后续文件较大，可迁移至 Supabase Storage 或其他对象存储。

### vector_store（向量存储，Spring AI 自动创建）

Spring AI pgvector 集成会在应用启动时自动创建此表（`initialize-schema: true`），无需手动建表。

## 五、验证初始化结果

在 Supabase SQL Editor 执行以下查询，确认所有表已创建：

```sql
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'public'
  AND table_name IN (
    't_knowledge_base',
    't_knowledge_document',
    't_knowledge_document_file',
    'vector_store'
  )
ORDER BY table_name;
```

预期返回 3 行（`vector_store` 在首次启动应用后才会出现）。
