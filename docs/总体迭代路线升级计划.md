## 二、Task（总体目标）

在不破坏现有 RAG 核心链路的前提下，分四个阶段把项目从"单体验证型后端"升级为"具备完整企业级基座能力、能理解意图并执行真实业务动作、且检索质量与工程化水平可量化评估"的 AI Agent 作品，同时完成仓库卫生清理和技术债务清偿。

## 三、Action — 分阶段路线图

### Phase 0：仓库卫生 + 低危速修

**目标**：清理误提交的敏感信息和大文件，修复 7 项无归属的低成本问题。

**前提条件**：无（可立即启动）。

**与后续阶段的依赖**：Phase 0 产出干净的仓库基线，后续 Phase 1/2 的代码变更都基于此基线，避免在脏仓库上继续叠加变更。

| 编号 | 任务 | 对应问题 | 备注 |
|------|------|---------|------|
| 0-1 | 清理 `demo/TestApiKey.java` 硬编码密钥，重写 git 历史 | H1 | 涉及 `git filter-branch`/`bfg`，需单独确认 |
| 0-2 | 删除仓库根目录 `org/`、`META-INF/`、`hs_err_pid*.log` | H2 | 添加到 `.gitignore` 并清理历史 |
| 0-3 | 删除 `src/main/resources/docs/pdf/`、`pdf2/` 下盗版 PDF，重写 git 历史 | H3 | 约 101MB，与 0-1 合并为一次历史重写 |
| 0-4 | `application.yaml` 数据库用户名改为 `${DB_USERNAME}` 环境变量 | M6 | 与其余密钥统一风格 |
| 0-5 | `GlobalExceptionHandler` 补充 `Exception.class` 兜底处理 | L1 | 一行代码，成本极低 |
| 0-6 | 删除 `pom.xml` 中注释掉的 `spring-ai-zhipuai` 依赖 | L2 | 死配置清理 |
| 0-7 | 更新 `CLAUDE.md` 项目描述为当前真实状态 | L3 | 参照本文档和代码扫描报告 |

### Phase 1：知识库入库 + 对话记忆 Redis 化

**目标**：修复 H7（竞态）、M5（非原子压缩）、M1（并发队列）、M2（熔断绕过）等正确性问题，落地入库异步化、MD5 去重、Redis 对话记忆新架构，清理死代码。

**前提条件**：Phase 0 完成（仓库干净）。

**为 Phase 2 提供的基础设施**：
- Redis 连接与配置（Phase 2 Sa-Token 会话持久化直接复用）
- 线程池/异步执行模式（Phase 2 租户上下文跨线程传递需要复用）
- `t_chat_message_raw`/`t_chat_message_compression` 两张新表（Phase 2 通过 `ALTER TABLE` 加 `tenant_id`）

**详细计划**：见 `docs/知识库入库与对话记忆Redis改造执行计划.md`。

| 模块 | 核心任务 | 对应问题 | 阻塞决策 |
|------|---------|---------|---------|
| 模块一：入库异步化 | 拆分事务边界修复 H7、MD5 去重、异步方案选型 | H7 | Q1(MD5 粒度)、Q2(重复判定)、Q3(线程池 vs MQ)、Q4(MQ 本地部署) |
| 模块二：对话记忆 Redis 化 | Redis 队列 + 分布式锁 + 压缩 + MySQL 双表 | M5, H8, M3, M4 | Q5(分布式锁选型)、Q6(新旧数据过渡)、Q7(压缩阈值)、Q8(死代码去留) |
| 模块三：遗留修复 | M1 并发队列、M2 熔断收口、H6 死代码 | M1, M2, H6 | Q9(本轮范围确认) |

**详细计划**：见 `docs/多租户RBAC与全链路监控看板迭代方案.md`。
