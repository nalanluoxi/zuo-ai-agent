## 一、Situation（背景/现状）

`zuo-ai-agent` 项目的 `CLAUDE.md` 中记录的项目描述仍停留在"早期初始化脚手架，仅有健康检查接口"的阶段，但实际代码已经发展为一个完整的 RAG + 对话 Agent 系统，覆盖：

- 多候选 Chat / Embedding 模型路由与熔断（`chat/`、`knowledge/embedding/`）
- 意图分类、查询改写、多通道检索、重排序（`intent/`、`rag/`）
- 文档入库流水线：分块、增强、向量化、写入向量库（`knowledge/ingestion/`、`pipeline/`）
- 三种对话记忆实现：DB / File / Map（`chatmemory/`）
- 知识库管理、RAG trace 记录（`knowledge/`、`trace/`）

文档与代码规模已严重不匹配，且仓库本身在长期迭代中混入了一些不该提交的内容。本次扫描目的是识别代码正确性问题、安全隐患、仓库卫生问题，为后续修复提供依据。仓库已配置远程 `origin` 并推送至 GitHub（`nalanluoxi/zuo-ai-agent`），意味着已发现的敏感信息可能已经处于公网可见状态。

## 二、Task（目标/待解决问题）

1. 扫描主流程代码（Chat/Embedding 路由熔断、RAG 流水线、对话记忆、入库服务、Controller、配置类）识别正确性与健壮性问题
2. 检查仓库内是否存在误提交的构建产物、崩溃日志、大文件、硬编码密钥等仓库卫生问题
3. 检查安全配置（CORS、鉴权、异常处理）
4. 输出问题清单并按严重程度分级，作为后续修复排期依据

## 三、Action（采取的方案/具体行动）

采用"人工检查关键配置文件 + Explore 子代理扫描核心业务代码"的方式并行进行，覆盖 `chat/`、`knowledge/embedding/`、`pipeline/`、`rag/`、`chatmemory/`、`intent/`、`knowledge/service/`、`controller/`、`config/`、`pom.xml`、`application.yaml` 及 `demo/` 目录下的遗留代码。

### 问题清单

#### 🔴 高危（High）

| 编号 | 位置 | 问题 |
|---|---|---|
| H1 | `demo/TestApiKey.java:4` | 硬编码 DashScope API Key（`sk-c17250cad5ef...`）明文提交进 git 历史，且该文件位于 `src/main/java`（非 test），会被打包进生产 jar |
| H2 | 仓库根目录 `org/`、`META-INF/`（约 280K）、`hs_err_pid*.log` ×3 | 反编译/解压的第三方 jar（spring-ai-ollama）内容与 JVM 崩溃日志被误提交进版本库 |
| H3 | `src/main/resources/docs/pdf/`、`pdf2/` | 3 个盗版电子书 PDF（来自 Z-Library）共约 101MB 被提交进 `src/main/resources`，构建时会被打包进最终产物 jar，存在版权风险且拖累仓库体积（`.git` 已达 113MB） |
| H4 | `config/CorsConfig.java:13-20` | `allowCredentials(true)` 与 `allowedOriginPatterns("*")` 同时使用，任意域名均可携带 Cookie 调用接口；项目未引入 Spring Security，无其他防护层 |

| H6 | `knowledge/embedding/RoutingEmbeddingService.java:55-96` | 遍历 Embedding 候选模型时未按 `provider` 字段分发，无论候选是 `ollama` 还是 `openai`，统一调用 `ollamaEmbeddingModel`，导致配置的 SiliconFlow 等候选实际从未被使用，静默路由错误 |
| H7 | `knowledge/service/impl/KnowledgeDocumentServiceImpl.java:50-98` | `upload()` 标注 `@Transactional`，内部却调用 `@Async` 的 `ingestionService.ingest(docId)`；异步线程可能在事务提交前执行 `selectById(docId)`，高并发下间歇性报"文档不存在" |
| H8 | `chatmemory/FileBasedChatMemory.java:42-45, 54-58` | `add(String, Message)` 是空方法（`//TODO`），`get(String)` 恒返回空列表，属于未完成的空壳实现，一旦被启用会静默丢失所有消息 |

## 四、Result（结果/结论）
