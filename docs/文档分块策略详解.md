# 文档分块策略详解

本文档介绍 `zuo-ai-agent` 中两种文档分块策略的设计思路、处理流程与适用场景。

---

## 一、固定大小分块（FixedSizeChunker）

**类路径**：`com.example.zuoaiagent.knowledge.chunk.strategy.FixedSizeChunker`
**策略枚举**：`ChunkingMode.FIXED_SIZE`

### 1.1 设计目标

按固定字符数滑动窗口切分文本，相邻块保留一定重叠量，同时在切分边界处尽量对齐到语义边界，减少句子被截断的情况。适用于 **PDF、TXT 等无明显结构的纯文本**。

### 1.2 处理流程

```
原始文本
  └─→ normalizeText()       文本归一化
        ├─ 去除 \r
        ├─ 修复 URL 跨行断裂（dingtalk.\ncom → dingtalk.com）
        └─ 修复中文软换行（商\n保通 → 商保通）
  └─→ 滑动窗口主循环
        ├─ targetEnd = min(start + chunkSize, len)
        ├─ adjustToBoundary()  语义边界微调（在 overlap 范围内回退）
        ├─ 保存 [start, end) 为一块
        └─ nextStart = end - overlap（保留重叠）
  └─→ 输出 chunks 列表
```

### 1.3 文本归一化（normalizeText）

归一化分两类场景处理：

#### URL 断行修复

检测到 `http://` 或 `https://` 后进入 `inUrl` 状态，遇到换行/空白时通过 `shouldJoinBrokenUrl` 判断是否合并：

| 触发条件 | 示例 | 行为 |
|----------|------|------|
| `.` 后紧跟字母 | `dingtalk.\ncom` | 合并换行 |
| URL 分隔符前 | `https://ex/\npath` | 合并换行 |
| URL 分隔符后 | `path\n?q=1` | 合并换行 |
| 下一行是数字列表项（`2.`、`10)`） | — | **不合并** |

URL 状态退出时机：遇到 CJK 字符/全角字符时主动退出；普通 ASCII 非 URL 字符（括号、`>` 等）不立即退出，由空白判断逻辑统一处理，避免 `https://example.com)` 中的 `)` 误终止状态。

#### 中文软换行修复

非 URL 状态遇到 `\n` 时：

- 前后均为 CJK 词字符（非标点）→ 直接去掉换行，如 `商\n保通` → `商保通`
- 否则保留换行，维持正常段落分隔

### 1.4 语义边界对齐（adjustToBoundary）

在 `[targetEnd - overlap, targetEnd]` 范围内向左回退，按以下优先级寻找最优切断点：

| 优先级 | 边界类型 | 说明 |
|--------|----------|------|
| 1 | `\n` 换行符 | 最优，天然段落边界 |
| 2 | `。！？` 中文句末标点 | 中文语义完整性 |
| 3 | `. ! ?` 英文句末标点 | 仅当后面是空白时才算边界；`!` 还需确认前一字符不是 URL 字符，避免切断 URL |

> **注意**：回退距离不超过 `overlap`，防止相邻块过度重叠。

### 1.5 滑动窗口主循环

```
start = 0
while start < len:
    targetEnd = min(start + chunkSize, len)
    end = adjustToBoundary(...)
    若 end <= start 或 end <= lastEnd → 强制 end = targetEnd（防死循环）
    保存 [start, end) 为一块
    nextStart = max(0, end - overlap)
    若 nextStart <= start → nextStart = end
    start = nextStart
```

**关键保护**：
- `overlap = min(overlap, chunkSize - 1)`，防止 overlap ≥ chunkSize 导致死循环
- 每轮必然推进，即使语义边界回退过头也会强制使用 `targetEnd`

### 1.6 参数说明

| 参数 | 含义 | 典型值 |
|------|------|--------|
| `chunkSize` | 目标块大小（字符数） | 500 ~ 1000 |
| `overlapSize` | 相邻块重叠字符数 | 50 ~ 200 |

## 二、结构感知分块（StructureAwareChunker）

**类路径**：`com.example.zuoaiagent.knowledge.chunk.strategy.StructureAwareChunker`
**策略枚举**：`ChunkingMode.STRUCTURE_AWARE`

### 2.1 设计目标

识别 Markdown 文档的结构层次，只在"块边界"处切分，保证代码块、标题、链接等结构元素的完整性。适用于 **Markdown 格式文档**。

### 2.2 块类型

| 类型 | 正则/规则 | 处理方式 |
|------|----------|----------|
| `HEADING` | `^#{1,6}\s+.*$` | 独立块，不与其他内容合并 |
| `CODE` | ` ``` ` 围栏包裹 | 整体作为一个块，内部不切分 |
| `ATOMIC` | 单行图片 `![]()` / 独占一行的链接 `[]()` | 独立块 |
| `PARA` | 其他普通行 | 按空行分段后参与预算合并 |

### 2.3 处理流程

```
原始文本
  └─→ 行尾统一（\r\n / \r → \n）
  └─→ segmentToBlocks()    扫描识别结构块
        ├─ 代码围栏：进入/退出 inFence 状态
        ├─ 空行：段落边界，提交当前 PARA 块
        ├─ 标题/原子行：独立提交
        └─ 普通行：并入当前 PARA 块
  └─→ coalesceGaps()       将块间空白间隙并入前一块
  └─→ packBlocksToChunks() 按 min/target/max 预算打包
  └─→ materialize()        物化为字符串，追加 overlap
  └─→ 输出 chunks 列表
```

### 2.4 块扫描（segmentToBlocks）

线性遍历每一行，维护三个状态：

- **`inFence`**：在代码围栏内，所有行直接累积，遇到结束 ` ``` ` 才提交 CODE 块
- **`inPara`**：在普通段落内，遇到空行/标题/原子行时提交 PARA 块
- 正常状态：识别标题和原子行，独立提交

扫描结束后调用 `coalesceGaps` 将相邻块之间的空白间隙并入前一个块，避免产生零散空白块。

### 2.5 预算打包（packBlocksToChunks）

参数关系：
```
target = chunkSize
max    = target * 4 / 3   （约 1.33 倍 target）
min    = target / 2        （约 0.5 倍 target）
```

打包策略（贪心）：

```
对每个 chunk：
  从当前块开始，不断向后合并，直到：
    ① 合并后超过 max → 停止（若当前 size < min 则忍一次超限）
    ② 已遍历所有块
```

**尾块优化**：最后一个 chunk 若过小（< min/2），尝试与倒数第二个合并（合并后不超过 max*2 才执行）。

### 2.6 物化与 Overlap（materialize）

```
对每个 [start, end) 范围：
  body = text[start:end]
  若 overlap > 0 且有上一块尾部 → body = prevTail + body
  记录本块尾部 prevTail = body[-overlap:]
```

> Overlap 是将上一块的末尾字符串**追加到下一块开头**，而不是像 FixedSizeChunker 那样通过 `nextStart` 回退实现，更适合块边界清晰的结构化文档。

### 2.7 参数说明

| 参数 | 含义 | 说明 |
|------|------|------|
| `chunkSize` | 目标块大小（字符数，即 target） | 内部派生 min = target/2，max = target*4/3 |
| `overlapSize` | 相邻块重叠字符数 | 追加到下一块开头，不影响块切分逻辑 |

## 三、两种策略对比

| 维度 | FixedSizeChunker | StructureAwareChunker |
|------|------------------|-----------------------|
| **适用文档** | PDF、TXT 等无结构纯文本 | Markdown 文档 |
| **切分依据** | 字符数 + 语义边界微调 | Markdown 结构块边界 |
| **代码块保护** | 无 | 整体保留，不拆分 |
| **标题处理** | 视为普通文本 | 独立块，保证语义完整 |
| **URL 保护** | 有（归一化 + 边界判断） | 不涉及（块级切分不触碰行内容） |
| **Overlap 实现** | 回退 start 指针 | 尾部字符串追加到下一块 |
| **大小控制** | 严格按 chunkSize 滑窗 | min/target/max 三档预算，弹性合并 |
| **未闭合代码围栏** | 不适用 | 整体作为 CODE 块输出（容错） |

### 选择建议

- 上传的是 **PDF 导出文本、日志、纯文字文档** → 选 `FIXED_SIZE`
- 上传的是 **技术文档、README、Wiki、含代码示例的 Markdown** → 选 `STRUCTURE_AWARE`
